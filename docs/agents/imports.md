# Imports: no barrel files

- Import every binding from the file that declares it: `@seawatts/db/schema/users`, `@seawatts/ui/button`, `./status`. Never add an `index.ts` or other file whose job is to re-export other modules, and never import a name through one. Biome's `noBarrelFile` and `noReExportAll` fail the lint on any `export … from` or `export *`.
- Why: a barrel puts every module of its folder, and everything those modules reach, into each page that imports one name from it. The dev server compiles and keeps all of it for every route, dev builds do not tree-shake, and a client component that reaches server code through a barrel ships it to the browser or breaks the build. In the app this rule came from, removing the barrels cut each page's own source graph by 40 to 50 percent and the dev server's memory per signed-in page by hundreds of megabytes.
- Give a package a wildcard entry (`"./*": "./src/*.ts"` in its `exports`) so any module is importable by its path. An `index.ts` that holds real code keeps its entry. A name that comes from another package is imported from that package, not re-exported.
- Tables too: import each from its own file under `packages/db/src/schema`, so a request loads only the tables its code uses.
- `biome.json` has two override lists. The first is the permanent one: config files that must re-export (PostCSS), Next.js route files that reuse another route's page, and the entry file of a package published to npm. The second lists the barrels that existed before this rule. That list only shrinks: when you touch one of those packages, move its importers to file paths, delete the barrel and remove its line. Never add to it.
